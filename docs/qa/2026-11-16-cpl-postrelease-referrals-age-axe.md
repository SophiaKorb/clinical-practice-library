## Finding F01 — axe's previously inconclusive rule: confirmed and addressed

The PR #43 retained `axe-results.json` stored only `incomplete:1` for the finder, so the initial report did **not** establish the rule ID. Re-ran the same pinned **axe-core 4.10.3 WCAG 2.0/2.1 A/AA** check with full rule/node logging on nonproduction source. It identified:

- **Rule:** `color-contrast`, axe impact `serious` (rule category, **not** a proven contrast failure).
- **Target:** the decorative `<span aria-hidden="true">⌄</span>` in the mobile `More` menu summary.
- **Reason:** axe check data `messageKey: nonBmp` / `Element content contains only non-text characters`. A manually inconclusive glyph contrast is **not** a confirmed WCAG failure.
- **Bounded fix:** replace the aria-hidden glyph with a CSS border/rotation caret in the finder; retain the native `details/summary` disclosure and `More` accessible name. Add exact regression tests to keep the caret visual-only and ensure zero axe incomplete results on the finder.
- **Re-evaluation:** at precursor commit `9114063816345313d0a8c180a665ff17b41a3f3c`, GitHub rendered QA run `43980077308` passed with `FINDER_AXE_INCOMPLETE_DETAIL []` and 209 targeted checks/0 failures. **Latest exact head must still pass** after final edits. This finding does not certify native VoiceOver/TalkBack/NVDA, actual zoom, contrast under all operating-system themes, or the rest of CPL.
